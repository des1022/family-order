# 家庭点菜小程序

仅限家庭内部使用的轻量点菜工具：菜品管理 → 点菜加购 → 提交订单 → 厨房汇总。
无注册登录、无支付、无分享营销，老人小孩 3 步就能下单。

技术栈：微信小程序原生开发 + 微信云开发（云数据库 + 云存储）。

## 二、部署步骤

### 1. 导入项目

1. 打开 **微信开发者工具** → 新建/导入项目 → 选择 `family-order` 目录。
2. `project.config.json` 中的 `appid` 默认是 `touristappid`，**必须替换成你自己的小程序 AppID**（个人主体即可）。
3. 右上角「详情」→ 本地设置 → 调试基础库建议选 **3.x**（最低 2.26.0，图片压缩接口要求）。

### 2. 开通云开发

1. 开发者工具左上角点击 **云开发** → 开通（选择 **免费额度** 按量计费即可）。
2. 创建一个环境，例如 `family-order`。
3. 复制 **环境 ID**（形如 `family-order-0gxxxxxxxxxx`）。
4. 打开 `utils/config.js`，把 `ENV_ID` 改成你的环境 ID：

```js
ENV_ID: 'family-order-0gxxxxxxxxxx'
```

### 3. 创建数据库集合

云开发控制台 → **数据库** → 新建集合，共 4 个：

| 集合 | 用途 | 说明 |
| --- | --- | --- |
| `dishes` | 菜品 | 需求指定 |
| `orders` | 订单 | 需求指定 |
| `categories` | 菜品分类 | 为实现「分类增删」新增 |
| `settings` | 管理密码 | 为实现「换设备也能用同一密码」新增 |

字段无需手动创建，插入数据时会自动生成。结构如下：

**dishes**
```
name        string   菜品名称（≤10 字）
category    string   分类
image       string   云存储 fileID
price       number   价格，默认 0（选填）
desc        string   描述（≤30 字，选填）
status      number   1 上架 / 0 下架
createTime  date     创建时间
```

**orders**
```
nickname    string   下单人昵称
goods       array    [{ id, name, image, price, num }]
remark      string   订单备注
totalNum    number   总数量
totalPrice  number   总金额
status      number   0 待制作 / 1 制作中 / 2 已完成
createTime  date     下单时间
```

**categories**：`name` string、`sort` number、`createTime` date
**settings**：只需一条 `_id` 为 `admin` 的文档 `{ password: "1234" }`，由首次设置密码时自动写入。

### 4. 设置数据库权限

数据库 → 对应集合 → **权限设置** → 选择 **自定义安全规则**，两个主集合按需求设置：

- `dishes`：所有用户可读，仅管理员可写
- `orders`：所有用户可读、可新增，仅管理员可修改状态、删除

> 说明：小程序端**没有登录体系**，云端无法识别「谁是管理员」。
> 因此实际落地为 **数据权限 =「所有用户可读，仅创建者可读写」**：
> 管理员的微信创建/修改菜品与订单，其他人只读 + 可下单，效果与需求一致。
> 管理页面另有一道 4 位密码（本地缓存 + 云数据库）防止家人误触。
> 如需严格服务端校验，可把写操作改造成云函数并在函数内校验密码（见「六、可选加固」）。

`categories` 与 `settings` 同样设为「所有用户可读，仅创建者可读写」；
`settings` 建议设为「仅创建者可读写」，避免密码被所有人读到。

### 5. 云存储

云开发控制台 → **存储** → 新建文件夹 `dish-images`。
菜品图片会上传到该目录，上传前自动压缩到宽度 ≤ 800px、体积 ≤ 200KB。

### 6. 预览与发布

1. 点击「编译」在模拟器查看；点击「预览」扫码在真机体验。
2. 确认无误后，点右上角 **上传** → 填写版本号与备注。
3. 登录 [微信公众平台](https://mp.weixin.qq.com) → 版本管理 → 提交审核（或设为体验版仅供家人使用）。

## 三、使用流程

### 家人点菜（3 步）

1. **点菜**：首页按分类浏览 → 点击菜品右侧「＋」加入购物车（可重复点，数量累加）。
2. **确认**：点底部购物车条 → 展开明细，可增减数量或清空 → 点「确认下单」。
3. **提交**：填写昵称（下次自动填充）+ 整单备注 → 提交订单，自动回首页。

### 厨房看单

「订单」页 → **待做清单**标签，自动把「待制作 + 制作中」的订单按菜品合并统计，
例如「番茄炒蛋 ×3 份」，并显示每道菜来自哪位家人。

### 管理员

1. 「我的」页最底部灰色小字 **家庭管理** → 输入 4 位数字密码（首次进入为设置密码）。
2. 菜品管理：按分类展示，支持上下架、编辑、删除（删除会同步删除云存储图片）。
3. 分类管理：增删分类；删除仍含菜品的分类时，会先把菜品转移到指定分类再删除。
4. 订单管理：按状态筛选，标记待制作 / 制作中 / 已完成，或删除订单。

## 四、需求实现对照

| 需求 | 实现位置 |
| --- | --- |
| 4 个主 tab（购物车底部悬浮） | tabBar 为「点菜 / 订单 / 我的」3 项，购物车为全局悬浮入口，常驻在 tabBar 上方 |
| 基础字号 ≥28rpx、按钮 ≥44px | `app.wxss` 全局字号 30rpx，`.btn` 最小高 88rpx（44px） |
| 图片懒加载、下拉刷新 | `components/dish-row` 使用 `lazy-load`；首页/订单/管理页支持下拉刷新 |
| 加购 toast、无阻塞弹窗 | 统一 `utils/util.js` 的 `toast()`，仅删除类操作用 `confirm()` |
| 仅展示 status=1 菜品 | `db.getOnDishes()` 过滤 |
| 数量减到 0 自动移除 | `cart.setNum()` |
| 昵称记忆 | 本地缓存 `fo_nickname` |
| 订单实时同步 | `db.watchOrders()` 基于云开发 `watch`，不支持时自动降级为进页面刷新 |
| 首启 1 页引导 | 首页 `showGuide`，记录于 `fo_guide_shown` |
| 骨架屏 / loading | `components/skeleton` + `wx.showLoading` |

## 六、可选加固（非必须）

当前管理写入走小程序端，配合数据权限已能满足「家人不会误改」的目标。
若希望密码真正具备服务端校验能力，可新建一个云函数（如 `adminOp`），
把 `db.js` 中的 `addDish / updateDish / removeDish / updateOrderStatus / removeOrder`
改为 `wx.cloud.callFunction`，并在云函数内比对 `settings/admin` 中的密码后再写库；
同时把 `dishes`、`orders` 权限收紧为「所有用户可读，仅管理端（云函数）可写」。

## 七、常见问题

**Q：页面一直提示「加载失败」？**
A：检查 `utils/config.js` 的 `ENV_ID` 是否与云开发控制台的环境 ID 完全一致。

**Q：新增菜品保存失败？**
A：多为集合未创建或权限不允许写入。确认 `dishes` 集合已建且权限为「仅创建者可读写」。

**Q：图片上传很慢？**
A：图片会先压缩再上传，属于正常耗时。若仍慢，可调低 `config.js` 的 `MAX_IMAGE_SIZE`。

**Q：换手机后管理密码不对？**
A：密码会同步到 `settings` 集合的 `admin` 文档。若云端读取失败，可手动在云数据库里查看/修改该文档的 `password` 字段。
